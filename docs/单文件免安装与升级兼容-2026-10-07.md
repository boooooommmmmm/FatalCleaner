# 单文件免安装与旧版升级兼容

日期：2026-10-07。状态：本地实现与验证完成，尚未发布；公开版本仍为 v0.23.1。本地预览仍使用 0.23.1 版本号，正式发布时必须递增版本。

## 用户拿到什么

- 新用户：下载 `FatalCleaner.exe`，双击运行，无需安装 .NET 或解压 ZIP。文件名应保留，自动更新按该名称定位程序。
- 旧用户：继续从原来的 `CleanSweep.exe` 检查更新，下载签名兼容 ZIP，原位更新。已有快捷方式、服务路径和程序入口继续有效。
- `FatalCleaner.exe` 后续自动更新仍只替换自己，保留同目录其他文件。旧安装继续维护完整兼容目录。
- 数据路径继续使用原有 `%ProgramData%\CleanSweep` / `%LocalAppData%\CleanSweep` 及 `$CleanSweep.Quarantine`，沿用原权限选择与迁移逻辑；设置、白名单、备份、数据库和隔离索引不因此次打包方式改变而迁移或重置。
- 单文件版包含运行时、原生库和三套签名数据集。运行时可能将原生组件解压至缓存；用户设置和隔离文件也继续持久保存，单文件指分发形式。
- 单文件版不安装后台服务，需要管理员权限时沿用“以管理员身份重新启动”。使用已安装提权服务的用户继续走原兼容包与原路径；服务的客户端路径/SID 校验未放宽。

## 两种发布产物

| 产物 | 内容和用途 |
| --- | --- |
| `FatalCleaner.exe` | 独立分发的压缩单文件 App，自包含运行时 |
| `FatalCleaner-win-x64-<版本>.zip` | 兼容自动更新：单文件 App 仍名为 `CleanSweep.exe`，另含 Service、服务运行时、外置签名规则、安装清单 |

`release/latest.json` 继续指向 ZIP，签名结构和密钥保持兼容。旧更新器必须先找到 `CleanSweep.exe` 并校验外置的 rules/fingerprints/popups；因此不能把 EXE 地址直接填进原来的更新清单，也不能删掉兼容 ZIP。

两个入口使用相同 App 二进制。新阶段三参数可携带目标文件名；旧客户端不传该参数时默认 `CleanSweep.exe`。单文件入口传 `FatalCleaner.exe`，事务只备份/替换该文件，不写 `install-files.txt`，也不停止其他安装的服务。

对于极早期没有安装清单的版本，新替换器只替换新包同名文件，保留无法确认归属的旧文件。此前“无清单就把整个目录文件都当作程序所有”的行为已修正；可能留下无法确认归属的旧 DLL。

## 实现

- Core 内嵌原始签名 JSON；App / Service 从内存验签、核对文件名与哈希，加载同一份已验证内容。在线数据仍须签名有效且版本更高，才覆盖内置基线。
- App 发布使用 `PublishSingleFile`、`IncludeNativeLibrariesForSelfExtract` 和压缩，不启用 `IncludeAllContentForSelfExtract`。已实际验证 `AppContext.BaseDirectory` 指向原 EXE 目录。机制参考 [Microsoft 单文件部署文档](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)。
- 内存和弹窗模块的受保护进程列表增加 `FatalCleaner.exe`。
- 设置页规则目录按钮改为查看在线规则更新目录；没有下载更新时说明当前采用内置规则。
- `tools/publish.ps1` 生成两种产物，拒绝非空/相互嵌套输出目录；同架构自动运行独立自检。旧输出应先归档，脚本不删除历史包。
- CI 的 Release 任务增加单文件发布与自检，尚未推送执行。

## 本地验证

完整 Release 验证：Core **554** + App **128** = **682 项通过**，构建零警告/错误；兼容包安装清单、版本、三套数据签名通过。包含前一轮未发布的开机加速配色改动。

新增 9 项回归覆盖：单文件更新只改自身、与旧安装并存时保留旧入口与安装清单、失败恢复旧 EXE、拒绝任意目标文件名、三套内嵌规则及无签名更新拒绝。既有无清单升级测试改为验证未知文件保留。

实际产物：`publish/singlefile-preview/FatalCleaner.exe`，71,771,016 字节，约 68.4 MiB；兼容目录 `publish/singlefile-compat-preview/`。`publish/win-x64` 原 v0.23.1 正式产物保留。

`--verify-portable` 在单实例、AppServices 初始化及启动维护之前退出，只验证内置签名、SQLite 内存数据库与 WPF 图标资源，不读取用户设置/隔离区，不联网或调用服务。PowerShell 7 与 Windows PowerShell 5.1 均已执行通过。

使用 v0.23.1 正式产物的旧 `CleanSweep.Core.dll` 实际调用 `VerifyAndExtract`：

1. 沿用旧 DLL 内的正式数据公钥，额外注入仅本轮验收使用的临时发布公钥；生产密钥不变。
2. 对新兼容目录生成测试 ZIP 与更高版本测试清单，旧验证器成功校验并解压。
3. 新替换器更新隔离的模拟旧安装，清除清单拥有的旧文件并保留用户文件；服务测试桩记录 stop/start。
4. 替换后的 `CleanSweep.exe` 运行独立自检通过；单文件路径更新后只保留 `FatalCleaner.exe` 与原用户文件，自检通过。

证据：`artifacts/verification/singlefile-2026-10-07/`；旧版兼容报告在其中 `legacy-upgrade/result.json`。

复验命令（输出目录必须是新的）：

```powershell
./tools/publish.ps1 -Out publish/compat-check -PortableOut publish/portable-check
./tools/verify-portable.ps1 -Exe publish/portable-check/FatalCleaner.exe
./tools/verify.ps1 -Configuration Release -PackageDir publish/compat-check -ResultsDirectory artifacts/verification/portable-check
dotnet run --project tools/CleanSweep.PackageCheck -c Release -- publish/compat-check publish/win-x64/CleanSweep.Core.dll artifacts/verification/portable-check/legacy-upgrade
```

PackageCheck 的第一参数必须是本轮脚本生成、支持 `--verify-portable` 的新包；旧包参数仅用于加载旧更新器，不能倒置。

未执行真实用户数据升级、UAC 切换账户、SYSTEM 服务替换、断电恢复或 ARM64 验收。测试清单的高版本号不代表正式发布版本，也不能替代真实权限场景的验收。
