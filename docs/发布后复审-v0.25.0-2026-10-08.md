## P1：切换运行用户后，历史依赖隔离项可能被自动永久删除

**定位：** `src/CleanSweep.Core/Cleaning/Quarantine.cs:325`（`PreserveDeveloperEntry`）；调用见 `PurgeExpired` 第 268 行、`EnforceSizeLimit` 第 289 行。

保护条件目前只有两项：隔离记录的 `ModuleId == "dev-cache"`，或构造 Quarantine 时传入的 PathGuard 识别原路径为开发依赖。PathGuard 的依赖根目录来自当前环境，无法识别另一个用户的默认依赖路径。

例如，旧版从“应用缓存”页清理的 Cargo/NuGet 文件，模块 ID 是 `app-cache`。此后另一个管理员运行应用、读到共享隔离索引或从同卷 sidecar 重建索引时，其护栏只包含该管理员自己的依赖根目录。原用户的 `.cargo/registry` 或 `.nuget/packages` 不再符合保留条件，到期或超额维护就调用 `Purge`，永久删除剩余恢复副本。

相关实际入口：

- `src/CleanSweep.App/App.xaml.cs:114`：启动时先 Reconcile，再自动到期/容量维护。
- `src/CleanSweep.App/Services/AppServices.cs:104`：隔离对象使用当前进程的 guard。
- `src/CleanSweep.Service/Program.cs:145`：服务以自己的 CurrentUserEnvironmentResolver 创建 guard；SYSTEM 的 profile 与客户端不同。
- `src/CleanSweep.Core/Elevation/ElevatedOperations.cs:99`：PurgeExpiredQuarantine 直接使用服务的共享 Quarantine，没有切换目标用户保护环境。

**触发条件：** 存在其他用户、非 `dev-cache` 模块的历史受保护依赖项；执行者能读取并删除该隔离副本；该项到期或隔离区超过上限。原事故中的 `dev-cache` 记录仍会被模块条件保留，不应把问题扩大成所有历史记录都会删除。

**复现：** 临时目录建立用户 A 的 `.cargo/registry/src/pkg/input.rs`，模拟旧版以 `app-cache` 隔离；对同一个临时数据库换用模拟 SYSTEM profile 的 guard，分别运行两类维护。

| 维护 | 用户 A 的 guard 识别保护 | SYSTEM 环境 guard 识别保护 | 删除数 | 副本仍存在 |
| --- | --- | --- | --- | --- |
| 到期淘汰 | true | false | 1 | false |
| 容量淘汰 | true | false | 1 | false |

这是环境与维护逻辑的隔离复现，没有安装服务或使用真实 SYSTEM 身份。

**建议：** 自动维护按隔离记录归属和可信用户配置识别保护，无法可靠识别时保留；新记录持久化开发数据保留属性，并对旧记录做兼容判断。不能只修改扫描页或服务的清理请求，启动维护、到期维护和容量维护都要覆盖。补充用户 A 创建/用户 B 维护、SYSTEM 维护、`app-cache` 旧记录、sidecar 重建后的回归。

## P2：构建产物会恢复历史勾选，连新生成的文件也被选中

**定位：** `src/CleanSweep.Core/Residue/BuildOutputScanner.cs:134`（创建 ScanItem）；`src/CleanSweep.Core/Safety/DeveloperCachePolicy.cs:10`；`src/CleanSweep.App/Services/AppSettings.cs:68`。

BuildOutputScanner 生成 `ModuleId = "build-output"` 的 Confirm 项，但没有设置 `RequiresFreshSelection`。DeveloperCachePolicy 只识别该标记、`dev-cache` 模块和 `dev.` 规则 ID，所以此项进入普通勾选恢复逻辑。

构建项的 ID 由项目目录生成；再次构建后 ID、Kind、Risk 不变，AppSettings 就恢复以前的 Selected=true。即便生成依据和文件集合已经变化，新文件也会一起被选中。开发者页同时明确说明“每次扫描后需手动确认”“构建产物默认不勾选”（ShellViewModel 第 155 行），实际行为与该承诺不符。

**复现：** 真实 BuildOutputScanner 首次扫描含一个输出的临时项目，记录选中；模拟下一次构建，更改 DLL 并新增另一个 DLL，更新生成清单，设为两天前，再次扫描。

```text
DefaultSelected = false
RequiresFreshSelection = false
sameId = true
evidenceChanged = true
oldFileCount = 1
newFileCount = 2
selectedAfterRescan = true
```

这是自动恢复勾选问题，仍需用户触发清理，不是后台自动清理；执行前的项目依据和进程复核不能补上缺失的本次选择。

**建议：** 构建产物显式设置 RequiresFreshSelection，确保旧设置中的选中状态被忽略。增加从实际扫描结果到 CleanSelectionTracker 的回归，覆盖同一项目新增/替换输出后重新扫描，以及普通非开发缓存仍可记住选择。
