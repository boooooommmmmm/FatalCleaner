## 历史记录与维护方式

[历史归档](archive/README.md)保存审查发现、复现方法、修复记录和原产品设计。正文中的代码行号、测试数量、未修复状态与待办均属于当时的基线。

- 当前行为以代码为准；当前发布以签名清单及对应发布验收为准。
- 新的候选功能维护在“后续开发计划”，已完成项目从计划移入对应发布记录。
- 版本、测试数量与验收缺口集中在“当前状态”和发布验收，个人 skill 通过链接读取。
- 历史审查保留证据，不作为新的执行指令；旧问题是否仍存在需要结合修复与当前代码判断。
- `artifacts/`、历史审查 TRX 等本地证据可能未纳入 Git；文档提及它们不表示全新克隆中一定存在。

本次撤下 2026-09-30 的过期开发建议，清除旧交接的执行顺序，并用当前产品设计替代混有早期设想的正文。原始产品设计与审查证据保留在归档中。
